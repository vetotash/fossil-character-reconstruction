Scope
This archive contains the 600-matrix fitted-method benchmark, the exact oracle
simulations and six-tip topology analysis, the new fitted-completion topology
searches, and Supplementary Figures S1 and S2. Historical matrices are supplied
in Historical_Supplementary_Code_and_Data.zip; the 180-matrix historical-layout
experiment is supplied in Layout_Supplementary_Code_and_Data.zip.

Environment and commands
Tested with Python 3.12. Install the versions in requirements.txt:
  python -m pip install -r requirements.txt
Run these commands from the archive's top-level directory:
  python run_analysis.py verify
  python run_analysis.py figures
  python run_analysis.py reproduce --output PATH_TO_NEW_DIRECTORY --workers 2
The reproduce output directory must not already exist. The supplied results
remain in simulation/results. Reproduction generates, fits and evaluates all
600 matrices. Matrix-level workers use separate processes; estimator seeds do
not depend on worker scheduling. Requirements: NumPy 2.3.5, SciPy 1.17.0,
scikit-learn 1.8.0, pandas 2.2.3 and matplotlib 3.10.8.

Twelve scenarios combine q = 0.03 or 0.3, 14 or 29 hidden tips per response,
and random, structured or statebiased masking. Each scenario has 50 independent
matrices. Each matrix has 48 tips and 40 independently evolved binary
characters: eight complete anchor columns and 32 response columns. The tree is
generated by uniform edge insertion, with unit edge lengths. The stationary
binary Mk root has equal state probabilities; q is the instantaneous
off-diagonal rate per unit branch length, not a rate per geological year.
random masks independently sample tips in each response without replacement.
structured masks reuse the tips nearest one randomly chosen anchor tip in all
responses, resolving distance ties by tip index. statebiased masks sample
without replacement with weights 4 for state 1 and 1 for state 0.

Method order: mode, knn5, logistic, extra_trees, nj_mk.
Scheme order: mode, knn5, logistic, extra_trees, nj_mk, nj_mk_joint.
mode uses observed state frequencies; knn5 is five-neighbour classification.
nj_mk_joint uses the same fitted model and marginal probabilities as nj_mk,
but samples tips jointly within a character. The other five schemes sample
cells independently using common uniforms. Each scheme supplies 512 draws.
Hard assignments use the maximum-probability state; exact ties select state 0.
The nj_mk_joint hard assignment is cellwise MAP, not joint MAP.

Seed sequences, with s = scenario ordinal and r = replicate index:
  trees:          [2026100403, s, r, 0]
  states:         [2026100403, s, r, 1]
  masks:          [2026100404, s, r]
  marginal draws: [2026100405, s, r, 0]
  joint Mk draws: [2026100405, s, r, 1]
Estimator random_state is 20261002. Fitting reads masked observations only;
generating trees, rates and hidden states are used for generation/evaluation.

Array formats
All indices are zero-based. NPZ files are NumPy compressed archives and can be
opened with numpy.load(path, allow_pickle=False). Matrix IDs are sSS_rRRR;
scenario ordinals are 0--11 and replicate indices are 0--49. Paths below are
relative to simulation/results.

inputs/{matrix_id}_masked.npz:
  X: int8 (48,40), taxa x characters; states 0/1, missing = -1.
  Columns 0--7 are complete; columns 8--39 contain the missing targets.
truth/{matrix_id}_truth.npz:
  X_true: uint8 (48,40), complete tip states.
  node_states: uint8 (94,40), states at tips and internal nodes.
  edges: int16 (93,2), pairs of node IDs; edge_lengths: float64 (93,), all 1.
  Tips are nodes 0--47; internal nodes are 48--93. Scalar root = 48.
  q: scalar generating rate; mask_anchor: scalar tip index for structured
  masking, otherwise -1.
predictions/{matrix_id}.npz:
  probabilities: float64 (5,48,40,2), method x taxon x character x state;
  state order is [0,1]. Observed cells retain their fixed one-hot states.
  target_indices: int16 (n_targets,2), exactly argwhere(X == -1), row-major.
  n_targets is 448 or 928 (32 responses x 14 or 29 hidden tips).
  missing_states_packed: uint8 (6,512,ceil(n_targets/8)), scheme x draw x byte.
  Bits use NumPy's default big-bit order. For scheme i, recover states with:
    numpy.unpackbits(a['missing_states_packed'][i], axis=1,
                     count=len(a['target_indices']), bitorder='big')
  Recovered columns follow target_indices; observed cells are unchanged.
evaluation/{matrix_id}.npz:
  D_samples, L_samples, M_samples: int16 (6,512), scheme x draw.
  hard_D: int16 (6,). old_L, old_M, true_L, true_M, true_D: scalar integers.
Matching prediction JSON files record fitted trees, classes, rates, observed
labels, diagnostics, seeds and hashes. Matching evaluation JSON files record
array/completion hashes and sampling seeds. Top-level JSON manifests describe
input files, generation, fitting and evaluation.

Scores and units
L is unordered binary Sankoff length on the fixed generating tree. M is the
sum of character minima: 1 when both states occur among observed values, else
0. For each completion, D = (L_complete - old_L) - (M_complete - old_M).
L, M, D and their errors, standard deviations, widths and MCSEs are measured
in parsimony steps. D is not topology error or a direct count of homoplasy.
Accuracy and probabilities are proportions, not percentages. Brier is the
mean class-sum squared probability error (range 0--2); log loss is the mean
negative natural logarithm (nats), flooring true-state probabilities at 1e-12.
Central 95% draw ranges use linear interpolation at quantiles 0.025 and 0.975;
endpoints count as included. These are conditional simulation ranges.

CSV dictionary
All CSV files have a header row and are comma-delimited. The first eight files
below are in simulation/results. Counts are integers unless averaged. Binary
flags are 0/1. Character indices are zero-based. Blank numeric fields denote
unavailable/not-applicable values; mk_optimizer_success may be 'not_run'.

1. scenario_registry.csv -- one row per scenario.
scenario_id: scenario key; ordinal: zero-based scenario number; q: generating
rate; missing_per_response: hidden tip count per response; mask_mode: masking
rule; n_tips, n_characters, n_complete_anchors: design counts; replicates:
independent matrices per scenario; draws: completions per matrix/scheme.

2. matrix_registry.csv -- one row per independent matrix.
Includes all scenario_registry columns, plus matrix_id, replicate (zero-based)
and masked_sha256/truth_sha256 (SHA256 of the corresponding NPZ file bytes).

3. matrix_results.csv -- one row per matrix and propagation scheme.
matrix_id, scenario_id, replicate, scheme: identifiers; n_targets: hidden-cell
count; accuracy, brier, log_loss: target-average state scores;
zero_true_probability_count: targets assigned exactly zero probability to the
true state; log_floor_count: targets with true-state probability below 1e-12;
mean_max_probability: mean highest state probability across target cells.
old_L/old_M: incomplete matrix length/minimum; true_L/true_M: complete true
matrix length/minimum; true_D: true completion's D; hard_D: cellwise MAP D;
hard_D_error: hard_D - true_D; hard_D_absolute_error: absolute hard_D_error.
mean_D: mean over 512 draws; mean_D_error: mean_D - true_D;
mean_D_absolute_error: absolute mean_D_error; sd_D: sample SD across draws;
mean_D_mcse: sd_D/sqrt(n_draws); lower95/upper95: central draw quantiles;
interval_width: upper95 - lower95; truth_in_interval: inclusive inclusion of
true_D; truth_below_interval/truth_above_interval: strict outside-range flags.
constant_response_count/nonconstant_response_count: response columns with
one/multiple observed training states; convergence_warning_count: response
fits with a logistic ConvergenceWarning; n_draws: completion count (512).

4. scenario_summary.csv -- one row per scenario and scheme.
Includes scenario_registry columns, scheme and n_matrices (50).
For each matrix_results metric named accuracy, brier, log_loss,
mean_max_probability, true_D, hard_D, hard_D_error, hard_D_absolute_error,
mean_D, mean_D_error, mean_D_absolute_error, sd_D, mean_D_mcse,
interval_width, constant_response_count or convergence_warning_count:
  <metric>_mean = mean across independent matrices;
  <metric>_mcse = sample SD across matrices divided by sqrt(n_matrices).
Thus scenario_summary.mean_D_mcse is the between-matrix MCSE of mean_D;
mean_D_mcse_mean averages the within-matrix, finite-draw MCSEs.
interval_coverage: fraction with truth_in_interval = 1; coverage_mcse:
sqrt(p*(1-p)/n_matrices); coverage_wilson_lower95/upper95: binomial Wilson
95% limits. count_truth_below_interval/count_truth_above_interval sum the
corresponding flags. zero_true_probability_total/log_floor_total sum the
corresponding target-cell counts. MCSEs and limits retain the metric's units.

5. paired_method_contrasts.csv -- all 15 scheme pairs per scenario.
scenario_id, reference, candidate: identifiers; n_matrices: paired count.
For accuracy, brier, log_loss, mean_D_error, mean_D_absolute_error,
interval_width and truth_in_interval, <metric>_difference_mean is the mean
candidate-minus-reference difference within the same matrices;
<metric>_difference_mcse is the sample SD of those paired differences divided
by sqrt(n_matrices). Units follow each underlying metric.

6. fit_character_diagnostics.csv -- one row per matrix/response character.
matrix_id, scenario_id, character: identifiers; n_train/n_test: observed/hidden
response counts; constant_fallback: one observed class; logistic_fit_ran:
classifier fit attempted; logistic_convergence_warning: warning flag;
logistic_reached_max_iter: iteration-limit flag; nj_zero_overlap_pairs:
taxon pairs with no jointly observed predictor; nj_negative_branches:
negative inferred edges; nj_truncated_branches: edges floored at 1e-8;
mk_rate: fitted off-diagonal rate per inferred branch-length unit;
mk_rate_boundary: abs(log(mk_rate)) >= 7.999 flag; mk_optimizer_ran:
optimisation attempted; mk_optimizer_success: optimiser success flag or
not_run; mk_warning_count: recorded Mk warning-message count.

7. fit_diagnostics_by_scenario.csv -- diagnostic totals by scenario.
scenario_id: identifier; response_fits: number of response records.
constant_fallback, logistic_fit_ran, logistic_convergence_warning,
logistic_reached_max_iter, nj_zero_overlap_pairs, nj_negative_branches,
nj_truncated_branches, mk_rate_boundary, mk_optimizer_ran and
mk_warning_count sum the corresponding character-level fields.
mk_optimizer_failed counts attempted optimisations without success.

8. zero_probability_by_scenario.csv -- target-cell totals by scenario/scheme.
scenario_id, scheme: identifiers; n_matrices: contributing matrices;
n_target_cells: total target cells; zero_true_probability_count and
log_floor_count: sums defined in matrix_results; zero_true_probability_proportion
and log_floor_proportion: corresponding counts divided by n_target_cells.

figures/figure_s2_input_table.csv -- plotting data by scenario/scheme.
scenario_id, q, missing_per_response, mask_mode, scheme and n_matrices identify
the condition. accuracy_mean/mcse, brier_mean/mcse and
mean_D_absolute_error_mean/mcse are the scenario-level summaries above.
coverage_count: matrices with truth_in_interval = 1; coverage:
coverage_count/n_matrices; wilson_lower95/wilson_upper95: Wilson 95% limits.
Independent replication for scenario summaries is the matrix, not the draw
or target cell.

Distributional evaluation (Supplementary Information S11)
The distribution_analysis directory contains a post hoc reanalysis of all 600
saved matrices. It includes CRPS, signed bias, interval width and inclusion,
state-loss partitions, and additive character contributions to D error.
The original predictors and completions are unchanged. Run from the archive root:
  python -m unittest discover -s distribution_analysis -p test_distribution_analysis.py -v
  python distribution_analysis/analyze_distributions.py --root . --output ../distribution_results --workers 2
The output directory must be empty or new and outside this archive. Saved
numerical results and their source hashes are in distribution_analysis/results.
distribution_analysis/README.txt defines all files, columns and units. Results
that use each matrix's evaluation truth to shift its predictive distribution
are stored separately as oracle_centered_diagnostic files; they are not valid
forecasts or demonstrated improvements. S11_summary_table.csv provides the
12-condition marginal-versus-joint Mk comparison reported in Table S24.

Oracle simulations and exhaustive topology analysis

The oracle/ directory retains exact conditional distributions for 48 scenarios
with 100 independent matrices each, together with all 105 six-tip unrooted binary
trees and all tied optimal-tree sets for the 24 six-tip scenarios. These methods
know the generating tree and transition parameter; they are theoretical checks,
not fitted empirical predictors. Source code and arrays retain their scientific
content. Run the portable saved-array replay from this archive root:

  python oracle/validation/replay_saved_arrays.py --output ../oracle_replay.json

This checks 14,400 exact matrix-method PMFs and 472,800 saved optimum-set bitsets.
For a new oracle simulation run, use a nonexistent output directory:

  python oracle/simulation/exact_simulation.py --self-test
  python oracle/simulation/exact_simulation.py --frozen-design oracle/ANALYSIS_PLAN.txt --output ../oracle_new

To recalculate all 105-tree evaluations of the supplied saved six-tip draws:

  python oracle/topology/run_topology.py --manifest oracle/topology/topology_input_manifest.json --output ../oracle_topology_new

Fitted-completion topology searches (Supplementary Information S14)

topology_extension/ contains actual searches on the same 600 source matrices,
with source-incomplete and truth-complete baselines, five distinct cellwise
maximum-probability completions, and eight fixed saved draws per scheme. The
main results in topology_extension/results_amended/ use three independent random
starts plus one NJ start inferred from each searched matrix, all followed by
the same strictly improving NNI search with a 200-move cap. The original three-
random-start results are retained in topology_extension/results/; the NJ start
was added as an explicitly post hoc amendment after baseline search failure.
All distinct lowest-score endpoints encountered across starts are retained.
This is a heuristic, not an exhaustive list of global parsimony optima. The
generating tree is used only for post-search evaluation. Draws and starts are
nested computations; MCSEs use 50 independent matrices per condition. See
topology_extension/README.txt for the full analysis history and file dictionary.

Portable topology checks and Table S28 recreation, from this archive root:
  python -m unittest discover -s topology_extension -p 'test_*.py' -v
  python topology_extension/validate_oracle_registry.py --oracle-root oracle --output ../topology_registry_check.json
  python topology_extension/summarize_topology_extension.py --results topology_extension/results_amended --output ../table_s28_replay

To repeat the amended search while reusing the supplied original endpoints:
  python topology_extension/run_nj_amendment.py --root . --original-results topology_extension/results --output ../topology_amended_replay --workers 6

The top-level run_analysis.py verify command checks the 600 original fitted-
method arrays. The separate oracle and topology commands above check their
additional analyses; none of these commands requires refitting the 600 models.
SHA256SUMS.txt lists every supplied file except itself using standard sha256sum
format. To verify file integrity independently, run sha256sum -c SHA256SUMS.txt.
